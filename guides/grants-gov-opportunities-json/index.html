US federal grant opportunities as JSON or CSV: the Grants.gov API, a Python example and a free sample

How to pull federal grant opportunities from Grants.gov yourself, which filters silently return nothing, how to get amounts and the real deadline, what the terms of service require, and when a normalized feed is worth paying for.

Updated: November 2026. API behaviour below was tested live on 5 November 2026.

This product uses the Grants.gov API but is not endorsed or certified by the U.S. Department of Health and Human Services.

The short version

  • Grants.gov lists US federal grant opportunities. Its official API has two POST endpoints that need no authentication: search2 (the list) and fetchOpportunity (the detail of one opportunity). The terms of service allow you to "search, display, analyze, retrieve, view and otherwise get" the data, and ask for a visible non-endorsement notice (quoted above and in section 5).
  • The search response is only a thin list. Amounts, eligibility, description and the real closing date need one extra call per opportunity. Several filters behave in ways that are not obvious: a bare department code like HHS matches nothing, only one ALN number can be filtered at once, and amounts are strings.
  • For a bulk or full-history load there is also a daily XML extract (about 78 MB). This page shows both, a script tested today and a free 20-record sample of normalized output.

1. The Grants.gov API

Documentation: grants.gov/api/api-guide; the guide states that authentication is not required for search2 and fetchOpportunity. Production host https://api.grants.gov. Both endpoints take POST with a JSON body; a plain GET returns HTTP 403 with an empty body, which is just the gateway.

curl -s -X POST https://api.grants.gov/v1/api/search2 \
  -H "Content-Type: application/json" \
  -d '{"keyword": "", "oppStatuses": "posted", "sortBy": "openDate|desc", "rows": 2}'

The response has data.hitCount (858 posted opportunities on 5 November 2026) and data.oppHits[]. One hit, as returned:

Each response also carries facet blocks (agencies, eligibilities, funding categories) and a token, so it weighs 11 to 14 KB regardless of rows.

Without oppStatuses, the default is posted plus forecasted. Pass several statuses pipe-separated: "posted|forecasted". An unknown status or filter value returns 0 hits, not an error.

Paging

  • rows is not capped at 100: rows: 5000 returned all 858 posted hits in one response. startRecordNum pages, and a start past the end returns an empty list.
  • There is no "updated since" filter, so to detect changes you must keep what you saw and compare.

The detail call

POST /v1/api/fetchOpportunity with {"opportunityId": 364212} returns a synopsis block (posted, closed, archived) and/or a forecast block, plus the ALN programs, agency details, attachments and application packages. Things to know:

  • Amounts are strings: "1500000", "none", an empty string or absent. estimatedFunding (total program funding) and awardCeiling are different things; the award ceiling alone understates a big program.
  • Dates are text: "Feb 04, 2027 12:00:00 AM EST". The midnight is a placeholder; the true cut-off time is in the announcement text. The search list uses another format, MM/DD/YYYY.
  • Descriptions are HTML.
  • Errors can arrive as HTTP 200. An unknown id returns errorcode 0 and a "no record found" message; check the body.
  • The contact fields can hold a person. The detail record carries a contact name, e-mail and phone; usually a program mailbox, sometimes a named officer. And synopsis.agencyName can contain that person's name instead of the agency, as it did for the NHTSA opportunity above, so take the agency from the search hit.
  • A record posted after a forecast carries both blocks; docType tells you which is current.
  • About 0.8 to 1.2 seconds per detail call. We found no documented rate limit; the terms reserve the right to block clients that "exceed or circumvent" limits, so keep a low concurrency (we use 4 in flight at about 5 starts per second).

The daily XML extract, for bulk loads

grants.gov/xml-extract lists the last seven daily files, GrantsDBExtract<YYYYMMDD>v2.zip, 78.4 MB each, rebuilt at about 04:40 US Eastern (the 4 November file is stamped 04:43:01 AM EST). One request gives you everything with amounts, instead of one detail call per opportunity. The cost is a bigger download and an XML parse, which is a poor trade for a small query and a good one for a full load.

2. DIY: posted opportunities to CSV in Python

This script (tested against the live API on 5 November 2026: 858 posted opportunities, 10 rows written) searches, fetches the detail of each hit, converts the string amounts and text dates and writes a CSV. It needs pip install requests.

import csv
import re
import time
from datetime import datetime
from html import unescape

import requests

BASE = "https://api.grants.gov/v1/api"
S = requests.Session()
S.headers["User-Agent"] = "my-grants-script/1.0"


def post(path, body):
    for attempt in range(5):
        r = S.post(f"{BASE}/{path}", json=body, timeout=60)
        if r.status_code in (429, 500, 502, 503, 504):
            time.sleep(2 ** attempt)
            continue
        r.raise_for_status()
        j = r.json()
        if j.get("errorcode", 0) != 0:                  # errors can come back as HTTP 200
            raise RuntimeError(j.get("msg"))
        return j["data"]
    raise RuntimeError("Grants.gov unavailable")


def money(v):
    """Amounts are strings: "1500000", "none", "" or missing."""
    try:
        return float(v)
    except (TypeError, ValueError):
        return None


def day(s):
    """'Feb 04, 2027 12:00:00 AM EST' -> '2027-02-04'"""
    try:
        return datetime.strptime(s[:12], "%b %d, %Y").date().isoformat() if s else None
    except ValueError:
        return None


# 1) Search: no key needed. Dates in the hits are MM/DD/YYYY. The agency filter needs "HHS*" or "HHS-NIH11", not "HHS".
hits = post("search2", {"keyword": "", "oppStatuses": "posted", "agencies": "",
                        "sortBy": "openDate|desc", "rows": 10, "startRecordNum": 0})
print(hits["hitCount"], "posted opportunities")

rows = []
for h in hits["oppHits"]:
    # 2) One detail call per opportunity gives description, amounts, eligibility, the real deadline.
    d = post("fetchOpportunity", {"opportunityId": int(h["id"])})
    syn = d.get("synopsis") or d.get("forecast") or {}
    desc = re.sub(r"\s+", " ", re.sub(r"<[^>]+>", " ", unescape(syn.get("synopsisDesc") or syn.get("forecastDesc") or ""))).strip()
    rows.append({
        "id": h["id"], "number": h["number"], "title": h["title"], "agency": h["agency"],
        "posted": day(syn.get("postingDate")), "deadline": day(syn.get("responseDate")),
        "total_funding": money(syn.get("estimatedFunding")), "award_ceiling": money(syn.get("awardCeiling")),
        "aln": ";".join(h.get("cfdaList") or []), "description": desc[:300],
        "url": f"https://www.grants.gov/search-results-detail/{h['id']}",
    })
    time.sleep(0.3)                                      # no documented limit; the terms allow blocking clients that exceed or circumvent limits

with open("grants_gov.csv", "w", newline="", encoding="utf-8") as f:
    w = csv.DictWriter(f, fieldnames=rows[0].keys())
    w.writeheader()
    w.writerows(rows)
print(len(rows), "rows written")

  • You may use the API to "search, display, analyze, retrieve, view and otherwise get" information from grants data.
  • Attribution is required. Services that use the API should display this notice prominently: This product uses the Grants.gov API but is not endorsed or certified by the U.S. Department of Health and Human Services.
  • You may use the Grants.gov name to identify the source, but not to imply endorsement.
  • You may not modify or falsely represent the content and still claim HHS Grants.gov as the source. Shortening a description or reformatting a date is presentation; do not alter the meaning of an announcement. Always link back to the opportunity page.
  • Grants.gov may limit access and may block clients that attempt to exceed or circumvent limits. The API is provided as is; the terms also contain warranty, liability and indemnification clauses.

This is a summary, not legal advice; the terms can change, so read the page itself. Personal data: contact names, e-mails and phones in announcements are officials' business contacts; our sample omits them.
