EU public tenders as JSON or CSV: the TED Search API, a Python example, and a ready-made dataset

How to pull contract notices and award notices from TED (Tenders Electronic Daily) yourself, which limits and field quirks to expect, and when a normalized feed is worth paying for.

Updated: November 2026. API behaviour below was tested live on 4 November 2026.

The short version

  • TED publishes EU public procurement notices. The official Search API v3 is free and needs no API key: one POST endpoint, a query language, JSON in and out.
  • Doing it yourself is easy for a one-off export. The work is in the details: sorting, pagination beyond 15,000 results, multilingual objects, repeated values and mixed types. This page lists the ones we hit.
  • If you want one flat schema, CPV labels, awards and a schedule without maintaining a script, we run an Apify Actor for that. Real samples of its output are at the bottom, free to download.

1. The official TED Search API

Documentation: docs.ted.europa.eu/api/latest/search.html. The docs describe the API as aimed at data reusers and not requiring authentication; that matches what we saw (anonymous requests return 200). There is also a Swagger UI at api.ted.europa.eu/swagger-ui and an OpenAPI file at api.ted.europa.eu/api-v3.yaml.

Endpoint: POST https://api.ted.europa.eu/v3/notices/search. The body is JSON with a query (the "expert query" language), a list of fields to return, and paging parameters.

curl -s -X POST https://api.ted.europa.eu/v3/notices/search \
  -H "Content-Type: application/json" \
  -d '{
    "query": "buyer-country=ITA AND classification-cpv=72* AND notice-type=cn-standard AND publication-date>=today(-14) SORT BY publication-date DESC",
    "fields": ["publication-number", "notice-type", "buyer-name", "buyer-country",
               "classification-cpv", "publication-date", "estimated-value-proc", "estimated-value-cur-proc"],
    "limit": 2,
    "paginationMode": "ITERATION"
  }'

Query syntax that worked

GoalQuery
Country of the buyer (three-letter ISO code)buyer-country=ITA or buyer-country IN (ITA FRA)
CPV prefixclassification-cpv=72* or classification-cpv IN (72* 45*)
Notice typenotice-type=cn-standard, notice-type IN (can-standard can-social)
Publication datepublication-date>=20261020 or publication-date>=today(-7)
Full textFT~("cybersecurity")
Buyer name wordbuyer-name~"comune"
Valuetotal-value>=1000000
Sort, newest firstappend SORT BY publication-date DESC to the query

Combine with AND / OR. A syntax error or unknown field returns HTTP 400 with a type such as QUERY_UNKNOWN_FIELD or QUERY_SYNTAX_ERROR and the column of the problem. Adding "checkQuerySyntax": true to the body validates a query without running it (documented in the OpenAPI file).

Sorting: it goes in the query, not in the body

This one cost us time. The request body has no sort parameters, and unknown body properties are silently ignored. We sent "sortField": "publication-date", "sortOrder": "DESC" and also ASC, with an invalid field name, and with an invalid order: the results were identical every time, oldest first (by publication number). The documented way is the SORT BY field DESC clause at the end of the expert query. With it, the same request returned notices from the current day first. Without it, "give me the last 50 tenders from the last 14 days" returns the oldest 50 of those 14 days.

Limits and pagination

  • limit is capped at 250. Asking for 300 returns 400 SEARCH_EXCEEDS_MAX_LIMIT. The OpenAPI file adds a second cap of 10,000 fields per page (length of fields times limit).
  • Page mode has a 15,000-result window. The default mode is PAGE_NUMBER and page x limit must stay at or below 15,000, otherwise 400 SEARCH_WINDOW_TOO_WIDE (for example page 61 with limit 250).
  • Use "paginationMode": "ITERATION" for bigger exports. Pass the returned iterationNextToken back as iterationNextToken until no more notices come back. We iterated 75 pages (18,750 notices) in one run, past the page-mode window. Per the docs this mode is consistent (a point-in-time snapshot), while page mode can show duplicates or gaps if a new Official Journal issue is released between your requests.
  • totalNoticeCount tells you how many notices the query matches, so you can size an export before running it. The response also has a timedOut flag; check it.
  • We found no documented rate limit and no rate-limit headers. We did see occasional 502 responses from the CDN in front of the API, so retry with backoff.

Field quirks worth knowing

Fields use eForms business-term names (title-proc, estimated-value-lot...). Asking for a field that does not exist returns 400 with the full list of supported field names. The shapes are not uniform:

  • Dates carry a timezone suffix: "2026-10-20+02:00". Cut to 10 characters for a calendar date.
  • Text is multilingual objects keyed by three-letter language code: title-proc is {"ita": "..."}, title-lot is {"ita": ["..."]} (lists), buyer-name is {"ita": ["..."]}. There is no translation: the text is in the buyer's language.
  • Same kind of field, different types: in one live query, estimated-value-proc was a string ("324000.00"), estimated-value-lot a list of strings and total-value an integer.
  • Repeated values: classification-cpv repeats a code once per lot. One notice returned 14 entries for 7 distinct codes. De-duplicate while keeping order.
  • HTML entities in text: 7 of 100 Italian contract notices we queried had titles containing entities such as &#8217; instead of an apostrophe. Run html.unescape if you display titles.
  • Country codes are three-letter (ITA) and returned as lists.
  • links comes back even if you did not request it, with one URL per language for HTML and PDF plus an XML URL.
  • Value fields depend on the form: contract notices usually fill estimated-value-proc; award notices carry result values and winners in separate fields. Older (pre-eForms) notices have fewer structured fields.

2. DIY: notices to CSV in Python

This script (tested against the live API on 4 November 2026, it returned 39 notices) pages through the results, retries on transient errors, flattens the multilingual fields and writes a CSV. It needs pip install requests.

import csv
import html
import time

import requests

URL = "https://api.ted.europa.eu/v3/notices/search"
FIELDS = ["publication-number", "notice-type", "title-proc", "buyer-name", "buyer-country",
          "classification-cpv", "publication-date", "estimated-value-proc", "estimated-value-cur-proc",
          "deadline-receipt-tender-date-lot"]
QUERY = "buyer-country=ITA AND classification-cpv=72* AND notice-type=cn-standard AND publication-date>=today(-14) SORT BY publication-date DESC"


def first_text(multi, langs=("eng", "ita")):
    """Titles and names come as {"ita": "...", "eng": "..."} (sometimes with a list value)."""
    if not isinstance(multi, dict):
        return multi
    for lang in (*langs, *multi):
        if lang in multi:
            v = multi[lang]
            return html.unescape(v[0] if isinstance(v, list) else v)  # some titles contain &#8217; etc.


def search(query, limit=250):
    body = {"query": query, "fields": FIELDS, "limit": limit, "paginationMode": "ITERATION"}
    while True:
        for attempt in range(5):
            r = requests.post(URL, json=body, timeout=60)
            if r.status_code in (429, 500, 502, 503, 504):
                time.sleep(2 ** attempt)
                continue
            r.raise_for_status()
            break
        else:
            raise RuntimeError("TED API unavailable")
        data = r.json()
        yield from data["notices"]
        token = data.get("iterationNextToken")
        if not token or not data["notices"]:
            return
        body["iterationNextToken"] = token


rows = []
for n in search(QUERY):
    rows.append({
        "id": n["publication-number"],
        "type": n.get("notice-type"),
        "published": (n.get("publication-date") or "")[:10],       # "2026-10-20+02:00" -> "2026-10-20"
        "title": first_text(n.get("title-proc")),
        "buyer": first_text(n.get("buyer-name")),
        "cpv": ";".join(dict.fromkeys(n.get("classification-cpv") or [])),  # de-duplicate, order kept
        "value": n.get("estimated-value-proc"),
        "currency": n.get("estimated-value-cur-proc"),
        "url": f"https://ted.europa.eu/en/notice/-/detail/{n['publication-number']}",
    })

with open("ted_tenders.csv", "w", newline="", encoding="utf-8") as f:
    w = csv.DictWriter(f, fieldnames=rows[0].keys())
    w.writeheader()
    w.writerows(rows)
print(len(rows), "notices")

3. When the Actor saves time

For a one-off look, the script above is enough and free. The Apify Actor TED EU Public Tenders (by Nexus Scrapers) wraps the same official API. It pays off when you would otherwise maintain that code yourself:

  • One normalized schema. Every item has the same keys: a buyer object, ISO 3166 country codes, money as {amount, currency}, dates as YYYY-MM-DD, a deadline with time and offset, unified notice types and procedure types. Missing values are null, never missing keys. The same schema is used by our UK Actor, so EU and UK tenders can go into one table.
  • CPV codes with official labels, deduplicated, in any of the 24 EU languages (cpvLabelLanguage), plus the main CPV and its division name. The labels come from the Publications Office's CPV 2008 vocabulary.
  • Award view. For award notices there is a dataset view with winners (name, country), awarded value and award date.
  • Filters as plain inputs (keywords, countries, CPV prefixes, notice types, date range, deadline, value, buyer name) instead of hand-written expert queries, with an expertQuery escape hatch.
  • Scheduling and integrations through Apify: run daily, then send the dataset to Slack, e-mail, Google Sheets or a webhook, or call it through the Apify API or MCP. Export as JSON, CSV or Excel.
  • Retries and pagination are handled, up to 15,000 results per run.

Pricing is pay per result: $0.002 per result at the time of writing; the Actor page shows the current price.

What it does not do: it does not translate notices, does not fetch tender documents (it links to the notice), and does not expose per-lot detail. If you only need a single export, use the script above.

5. Data licence and attribution

The TED legal notice says the European Commission's reuse policy is implemented by the Commission Decision of 12 December 2011 on the reuse of Commission documents (2011/833/EU), and that, unless otherwise noted, procurement notices published in the Supplement to the Official Journal of the European Union can be freely reused for commercial or non-commercial purposes. In practice: credit the source (for example "Source: TED, Publications Office of the European Union") and indicate if you changed the data. The editorial content of the TED websites is CC BY 4.0. Notices can contain names of natural persons (sole traders, contacts), so handle them in line with GDPR. CPV labels come from the CPV 2008 vocabulary of the Publications Office (Regulation (EC) No 213/2008). This is a summary, not legal advice; read the legal notice for the exact terms.
